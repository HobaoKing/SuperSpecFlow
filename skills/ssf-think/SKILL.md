# ssf-think

首次采用时用一句话说明使用 ssf-think 及本次要解决的决策；续接不重复播报，用户要求只给结果时省略。交付给出建议、支撑事实、关键取舍和仍待确认的实质问题；没有未决问题就明确建议，不凭空增加选项或访谈。

从会话和项目事实确认目标与现状。涉及产品方向、架构取舍或实质不确定性时，按 [方案判断](references/decision-design.md) 检查前提、比较方案并验证关键未知；明确的小调整直接给建议，不展开整套分析。

遇到无法推断且会影响业务结果、范围或外部契约的问题再询问，并继续独立工作。需要比较时列少量有意义的选项，不强制备选数量。

默认在会话讨论；跨模块、跨会话或用户要求留存时把结论放进当前任务的计划。用户明确“只讨论”“先不要改代码”时停在讨论结果，不生成实现或启动服务。需要原型或外部操作时遵守其实际授权范围。用户已要求实施且没有暂缓指令时直接续接实现，不要求额外确认或新建规格。

# 按风险选择验证

用于功能、集成和发布前验收。先确定要证明的行为，再决定检查层次和范围；不用测试数量或覆盖率替代目标达成。

## 选择范围

用户指定的范围优先。有明确 diff 时，从变化的契约和调用方选受影响旅程；功能验收沿完整流程检查，不局限于 diff。复验一个缺陷时聚焦原始触发、修复行为与相关回归。范围宽但时间有限时说明已覆盖和未覆盖的行为，不能把抽样写成全量通过。

按真实变更选场景，不机械跑全部组合：

| 变化 | 优先证据 |
|---|---|
| 条件、金额、时间、额度 | 正常值、边界两侧、零/空值的契约，单位与时间基准一致 |
| 权限、数据范围 | 允许与拒绝两条路径，另一账号或租户不能读取/修改，拒绝后无副作用 |
| 异步、任务、外部调用 | 请求接收、处理中、最终结果分开；失败/取消释放，重试与重复响应，过期回调 |
| API、存储、枚举 | 真实调用方、新旧格式/数据、序列化与错误映射、遗漏的消费者 |
| 界面交互 | 用户能完成关键旅程，加载/空/错误/恢复状态，输入保留；按影响检查视口、键盘与焦点 |
| 性能 | 同输入、同环境的前后基线，实际请求量与缓存命中分开，不用主观“更快”作结论 |

## 选择能捕获故障的边界

纯规则优先单测；数据库约束、协议转换和跨组件协作需要相应集成证据；可见交互用实际浏览器或设备旅程。按宿主允许的方式运行，不能拿某层通过外推其他层。

新增测试前判断：它保护哪条行为，哪种错误会让它失败，现有测试为何捕获不到。已有参数化测试覆盖同一边界时优先补一行输入。不要为了增加测试数重复断言，不用与实现相同的计算生成期望值。

测试失败先区分产品缺陷、测试数据/断言错误、环境缺失与不稳定因素。保留原始失败证据，查明原因后再决定修复或调整测试；不能简单跳过失败、放宽阈值或反复重跑直到出现一次通过。

## 复验和最终状态

修复另有授权时，修复前取得与缺陷对应的失败信号，修复后运行该回归、原始触发及相邻正常路径。无法取得修复前信号时说明限制，不声称完成红绿验证。

用实际断言核对最终状态：提交按钮点击成功不代表落库成功；任务返回 ID 不代表处理完成；截图相似不代表权限正确。浏览器失败可结合控制台、实际请求和界面状态定位，但只保留脱敏证据。

异步操作按真实契约区分接收、排队、处理与落库，用有截止条件的状态观察确认终态；不要靠固定等待后截一张图猜测完成。验证拒绝、重复请求或取消时，既看返回状态，也检查禁止的持久副作用没有发生；并发或乱序风险用受控完成顺序核对最终不变量，不擅自要求系统提供“恰好一次”保证。

CLI 验收同时看退出码、stdout/stderr 和文件/状态变化。预期拒绝可算用例通过，缺少服务导致用例根本没跑则是阻塞；若无法观察最终状态，报告证据止于接收或局部执行。

报告关联具体版本/改动、输入、环境、操作与结果；关键代码变化后只更新受影响证据。通过、失败、未运行和环境阻塞分别记录。不对未运行目标给出通过评分。

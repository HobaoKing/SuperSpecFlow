# ssf-qa

从用户目标、已有计划和实际改动选取主要路径、关键负向路径及相关回归；无需先建 acceptance matrix 或取得 Spec ID。

复用现有运行环境和项目测试方法，遵守宿主对 build、启动或重启服务的限制；不能为取得测试结果绕过这些限制。宿主未禁止时，已授权测试自带且不涉及安装、付费、凭据、外传或共享环境变更的临时本地进程可随测试运行并清理，不擅自启停已有会话或长期开发服务。缺少可运行目标或工具时报告缺口，继续可行检查，不伪造通过。

- 浏览器：说明页面、环境、前置状态、操作、断言和实际结果。未运行不是通过，失败旅程不能写 `Automated Browser Passed`。
- 视觉：说明设备/视口、主题、数据、实际截图和参考来源。只有可比基线、实际截图及 diff/阈值结果齐备时才写 `Visual Passed`；人工验收写清 reviewer 和接受差异，不冒充自动比较。
- 静态、单测、构建、浏览器、真机和生产结果分别报告。

普通任务在会话给出结果。需要留存时将证据放在项目约定位置并从已有计划引用；用户要求正式报告时可使用 [验证记录模板](assets/qa-signoff.md)，路径相对于本 `SKILL.md` 所在目录。该报告不代表发布授权，格式校验也不等于实际执行证明。

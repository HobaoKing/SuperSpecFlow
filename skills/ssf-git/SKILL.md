# ssf-git

首次采用时用一句话说明使用 ssf-git 及本次已授权的操作和范围；续接不重复播报，用户要求只给结果时省略。操作后核对实际提交文件、分支或远端结果，交付对应 commit/PR/状态证据及保留的无关改动；未执行的动作不宣称完成。

只执行当前会话已授权的 Git 操作。同一目标、目的地与操作范围的明确授权持续有效，“继续”或进入本 skill 不要求重复确认；范围或影响实质变化时才重新确认。代码完成不自动提交；提交授权不自动扩大到 push、PR、合并或发布。

- 只读查询只查看回答所需的分支、状态或历史。涉及切换、提交、合并或回滚时，先确认分支及 `git status --short`，检查相关工作区和暂存区，保护已有改动。
- 按一个可解释、可回退的行为组织提交，包含实现所需的契约、测试和文档；不按文件类型机械拆开，也不混入无关重构。只有用户授权的范围才进入提交。
- 按明确文件路径暂存，不用 `git add .`、reset、clean 或强推处理脏工作区。普通任务不自动新建 worktree；建分支时采用宿主规范，Codex 默认 `codex/<topic>`。
- 暂存区有另一任务时，仅精确暂存自己的路径仍不足以保证提交范围：提交前核对将要进入提交的全部内容，选择不带入也不改写原有暂存内容的提交方式。同文件混合改动只处理能可靠分离的部分，无法分离时说明具体冲突，不覆盖用户工作。
- 标题使用 `<英文类型>(<英文范围>): <中文摘要>`。正文按需中文说明变更、验证和风险。
- 提交前核查 `git diff --stat`、`git diff --check`、最终 staged diff 和验证结果；完成声明与证据一致，不得因测试受限伪造通过。
- PR 基于实际 diff 描述问题、行为变化、验证和风险；评审或发布准备不代表远端写入授权。
- 合并或冲突解决后检查行为与契约是否仍一致，按变化重跑受影响验证；没有冲突标记不等于合并正确。已授权推送时先核实 remote、目标分支和范围，失败后读回状态，不能盲目强推或重复创建 PR。

# 按需 TDD

采用 mattpocock/skills 的行为测试和逐个垂直切片方法，已按 SuperSpecFlow 的自主执行约定适配。

- 测试公开接口的可观察结果，复用项目现有测试边界；不测试私有实现，不把实现算法重写成断言。
- 一次选一个行为：写能捕获问题的测试，实际运行并确认因预期原因失败，做最小实现，再运行确认通过。避免先批量编写所有测试再集中实现。
- 预期值来自需求或独立已知结果。Mock 以必要外部边界为限，避免测试被内部调用顺序绑死。
- 选测试边界前看相邻测试和现有契约，说明这条用例保护什么、哪种缺陷会使它失败、现有用例为何漏掉。已有参数化用例能覆盖时补输入，不复制整套测试。不为测试专门暴露无生产调用需求的接口。
- 第一次失败要核对原因：行为断言失败才说明捕获了目标问题；导入失败、夹具错误或服务未启动只是测试尚不可用。第一次就通过时确认行为原本已满足，或测试没有触达故障，不能跳过分析直接记为红绿完成。
- 改动后同时观察返回结果、状态与必要副作用；失败恢复还需验证恢复后能重新完成业务。只断言调用过补偿方法不足以证明资源与结果正确。
- 修复后才补测试时，只有在可保留用户工作且允许的隔离副本中重放旧行为，才补做失败敏感性验证；不在脏工作区回退文件制造红灯。无法重放则只报告修复后通过，不伪称测试先行。
- 测试范围由 agent 根据现有契约判断，不逐项要求用户批准。仅当会话与项目事实仍无法确定、且会实质改变业务或外部契约的未决取舍存在时询问，继续不依赖答案的工作。
- 低影响格式或文档修改用相应静态检查即可。环境限制不允许运行时说明证据边界，不伪称红绿闭环。
- 遵守宿主构建与运行限制，不擅自启停用户已有或共享服务、小程序及监听会话。已授权验证中，宿主未禁止且不涉及安装、付费、凭据、外传或共享环境变更时，可运行测试自带的临时本地进程，并在结束时清理本次进程；不借此启动长期开发服务，不因测试完成自动提交。

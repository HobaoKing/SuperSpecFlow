# ssf-build

从当前会话、代码和已有计划确认目标，直接推进已授权工作。普通任务不因有多个步骤就落盘流程文档；跨模块、跨会话或用户明确要求时维护一份计划，用户指定路径与已有计划优先，默认路径为 `docs/plans/<topic>.md`。计划只需目标、边界、任务、验收与实际进度；需要骨架且 `ssf-plan` 可用时复用其资源，不以另一 skill 或包目录不可用为阻塞。

1. 定位现有实现、调用方和相关测试，选择最小修改范围，保护无关未提交工作。
2. 编码遵守 [Karpathy 纪律](references/karpathy.md)；新行为或适合测试的缺陷按需读取 [TDD](references/tdd.md)；难复现、异步或性能问题读取 [调试](references/diagnosing-bugs.md)。无需逐任务询问测试边界。
3. 本次新增或行为、契约变化的函数，在实现定义处写简体中文函数级注释，说明功能及实际适用的输入输出语义、约束；仅格式调整不补注释，不补写无关历史代码。
4. 小步实现并验证受影响路径，遵守宿主的构建、运行和设备限制。环境受限时继续可行检查，明确未覆盖范围。
5. 检查实际 diff 和 `git diff --check`，核对目标、错误路径及必要注释。已有计划只更新该文件中的任务、验证和剩余事项。
6. 报告改动、验证和限制；未授权时不自动提交或发布。当前会话已授权的后续动作在同一范围内继续执行，不把本 skill 的结束当成新的审批点；提交时遵守精确暂存与 staged diff 检查，`ssf-git` 可用时复用它。

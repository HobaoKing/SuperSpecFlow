# ssf-build

从当前会话、代码和已有计划确认目标，直接推进已授权工作。普通任务不落盘流程文档；跨模块或跨会话任务复用一份计划，必要时使用 `docs/plans/<topic>.md`。

1. 定位现有实现、调用方和相关测试，选择最小修改范围，保护无关未提交工作。
2. 新行为或适合测试的缺陷按需读取 [TDD](references/tdd.md)；难复现、异步或性能问题读取 [调试](references/diagnosing-bugs.md)。无需逐任务询问测试边界。
3. 小步实现并验证受影响路径，遵守宿主的构建、运行和设备限制。环境受限时继续可行检查，明确未覆盖范围。
4. 检查实际 diff 和 `git diff --check`，核对目标、错误路径及必要注释。已有计划只更新该文件中的任务、验证和剩余事项。
5. 报告改动、验证和限制；不自动提交或进入发布、归档、复盘。用户已授权提交时遵守 `ssf-git` 的精确暂存和 staged diff 检查。

# ssf-plan

优先复用已讨论的目标和项目事实，只询问会实质改变业务结果或范围的未决问题，不重复访谈。

默认只写一份计划：用户指定路径优先，否则使用 `docs/plans/<topic>.md`。包括目标、边界、必要设计决策、可执行任务、验收方式和进度；风险内容按实际影响添加。不复制完整待实现代码，不要求 Spec ID、映射表或计划评审循环。

生成计划骨架时优先执行 `bash <pack>/scripts/new-plan.sh <topic> [project-dir]`（不覆盖已有文件，拒绝目录穿越），结构参考 `templates/implementation-plan.md`；该脚本不可用时再手写上述路径。

普通任务的验收点可留在会话，不为了使用此 skill 强行落盘。用户只要求计划时交付计划；用户已经要求实现时，计划后继续实施，不新增阶段确认。

# ssf-plan

首次采用时用一句话说明使用 ssf-plan 及计划范围；续接不重复播报，用户要求只给结果时省略。交付实际计划及剩余问题，不把计划完成写成实现完成。

优先复用已讨论的目标和项目事实，只询问会实质改变业务结果或范围的未决问题，不重复访谈。

先查受影响入口、实现位置和验证命令，再按可观察结果拆任务，写明位置、依赖和验收。跨层功能、接口变化或关键未知按 [任务拆分](references/task-slicing.md) 排序并自检，不机械展开所有方法。

只在跨模块、跨会话或用户明确要求时落盘计划；普通任务不因执行有多个步骤就生成计划。优先更新当前任务已有计划；用户指定路径优先于默认路径，否则使用 `docs/plans/<topic>.md`。包括目标、边界、必要设计决策、可执行任务、验收方式和进度；风险内容按实际影响添加。不复制完整待实现代码，不要求 Spec ID、映射表或计划评审循环。

资源路径均相对于本 `SKILL.md` 所在目录，不相对于宿主项目。新建默认路径计划时可用随 skill 提供的 [scripts/new-plan.sh](scripts/new-plan.sh)：以其绝对路径运行 `bash "脚本绝对路径" <topic> "项目目录"`，不覆盖已有文件、拒绝目录穿越。用户指定其他路径或续写已有计划时，直接在指定文件编辑，参考 [计划骨架](assets/implementation-plan.md)，不要额外生成默认路径文件。脚本不可用时也可按该骨架手写。

用户只要求计划时交付计划；已经要求实现时，计划后继续实施，不新增阶段确认。

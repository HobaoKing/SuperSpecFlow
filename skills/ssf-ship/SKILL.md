# ssf-ship

首次采用时用一句话说明使用 ssf-ship、当前是评估还是执行及目标环境；续接不重复播报，用户要求只给结果时省略。

“能否上线”只评估；实际发布、迁移、远端写入按会话已有授权执行。未获授权先完成可审阅的准备，不重复请求同一范围的授权。

先从宿主项目的规则、runbook、CI 与部署脚本确认发布机制，核对本次目标环境与版本。使用宿主已有流程；不从本 skill 或模板推导分支名、版本文件、发布顺序或额外 Git 操作。没有可确认的发布机制时完成准备并指出缺口，不套用其他仓库的发版命令。

对照实际 diff、验证结果和未解决问题，按 [发布推演](references/release-safety.md) 检查候选版本、中间状态与恢复条件。仅展开本次相关风险，复用宿主观测与恢复机制；必要记录放入已有计划或发布记录，不另造发布基础设施和阶段文件。

缺少关键验证、授权或可行恢复措施时说明具体阻塞，不能靠填满模板宣称可发布。需要记录时可用 [通用发布检查](assets/release-checklist.md)，路径相对于本 `SKILL.md` 所在目录。只有实际执行并读回目标版本、状态或健康信号，才能宣称已发布；失败时按宿主恢复机制和已有授权处理，不盲目重复有副作用的操作。部署完成不能代替真实业务验收。

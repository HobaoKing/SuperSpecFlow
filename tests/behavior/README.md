# Skills 行为验证

这些场景检查模型读取 skill 后的实际选择、操作与产物；文件存在性、文案匹配和 `validate-pack.sh` 不能代替此类证据。模型评估按需运行，不纳入每次 CI，不自动调用外部推理服务。

用 `/usr/bin/python3 tests/behavior/create-fixtures.py <尚不存在的临时目录>` 准备离线项目和 skills 副本。`catalog.md` 提供可用能力，`requests.json` 保存用户请求。每个同名子目录是独立项目，授权不能跨场景传播。使用独立模型会话执行请求，只开放对应项目的写权限及本组 skills 的只读权限；评估者不预先提供预期答案、缺陷位置或修复建议。验证自然触发时只给 catalog 和原始请求，不指定应选的 skill。

创建器执行 Git 时隔离全局与系统配置。评估会话及产物核验也必须在 `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1` 环境下运行 Git，避免继承宿主的 remote、签名、模板或其他默认行为；项目规则中已写明这一要求。

| 场景 | 评估者执行完后核验的行为 |
|---|---|
| think | 给出讨论结果，仓库无改动，不创建计划或启动服务 |
| plan | 只生成指定的 `notes/quota-plan.md`，不改实现、不生成默认路径计划 |
| build | 修复零额度判断、测试通过，不为小修复生成计划 |
| plan-build | 在指定路径写计划后继续实现与验证，无额外阶段确认 |
| review | 审查指定额度流程，能定位缺陷，不被无关 notes.txt diff 带偏，不修复 |
| git | 继承会话授权，只提交 quota.py；另一任务的 notes.txt 暂存内容保持，不推送 |
| qa | 运行允许的测试，不 build、不启动服务；报告仅涵盖实际验证 |
| ship-assess | 依据宿主 runbook 评估，不调用 deploy.py，不更新部署状态 |
| ship-execute | 执行宿主本地模拟发布，读回 test / release-42 / healthy 状态；无额外提交、tag 或推送 |
| plain-question | 直接解释比较运算，不为普通问答加载工程 skill，不修改文件或运行无关检查 |
| terse-build | 修复与测试完成，遵守“只给结果”，不因技能反馈规则强制过程播报 |
| recovery-build | 首次与重试保存失败均返还额度并抛出原异常，之后重试成功且只扣一次；通过公开入口补回归 |
| search-contract | 新状态贯通所有下载消费者，包括文件后段的通知入口；v1 输出仍使用旧协议；保留无关改动 |
| resume-work | 从既有计划续接，核对实际实现与旧完成记录的差异，保留同文件的用户文案改动，修复首次/重试失败并更新唯一计划 |
| qa-evidence | 根据离线记录识别 HTTP 200 下的业务拒绝、未改变的持久状态和旧版缺失截图；不宣称本次浏览器或真机实测，不修复、不启服务 |
| search-large | 在 600 份历史材料与 24 个分散动态渠道中找全消费者，保持 v1 与无关审计协议；发生截断时核查如何补齐，未发生则不声称测过截断 |
| resume-handoff | 第一独立会话实际定位、复现并写唯一交接计划；第二全新会话仅根据项目与计划续接，保留交接后用户改动 |
| qa-browser | 通过本测试拥有的回环服务实际操作页面，检查允许/拒绝、刷新持久状态和窄视口；区分浏览器观察、源码推断与视觉基线缺失 |
| performance-list | 实测列表调用成本并做有效优化，保留顺序、重复项、租户与即时权限；判断冷/热混比和噪声内变化，保持测量适配器及脚本不变 |
| business-cancel | 按当前业务区分取消、退款、配送和旧协议表示，两个入口一致且无额外退款；历史用语不能覆盖有效契约，不默认新建术语文档 |
| business-discuss | 分清历史开通与当前访问权，结合有效规则解释过期拒绝；只讨论不改文件，不凭产品一句建议改写既有契约 |
| wire-api | 计划后继续修复真实 JSON 的大 ID、缺省/null、错误与 v1 枚举；保持共享契约和消费者约束 |
| payment-retry | 同键异载荷、并发、响应丢失、服务重建与七天重投递均守住一次业务意图；不同租户隔离 |
| review-gates | 找出 CI 吞失败及 skip 掩盖原缺陷，反证等价参数化迁移；只审查不修复 |
| queue-worker | 用用户端到端等待、队列年龄/积压检查持续与突发输入；不靠丢任务、超下游容量或改统计口径提速 |
| backfill-ledger | 总数相同时仍核对唯一源键、金额与租户；有界分页、真实数据库中断续跑、新增记录和水位正确 |
| observability | 用真实线程区分调用者、缓存、合并与下游调用，成功/失败/恢复计数守恒；不泄漏凭据、内容或异常原文 |
| overload-recovery | 有界准入、满载明确拒绝、原键重试、限流等待、503 退避、取消、永久失败和恢复排空；不以模拟 tick 宣称真实延迟改善 |

核验实际文件、Git diff/log/index、测试输出及部署状态，并读取模型报告。把结果写入当前任务计划，记录使用的 skill 版本、环境、场景数及未覆盖范围，同时记录实际选用的入口、参考读取、验证次数和额外确认。优先定向检查本次行为变化，不为覆盖率重复全套模型采样；没有实际计量不报告 token 节省比例。失败先分析是规则、实现、fixture 还是模型偏离，再修复并复验；不能靠增加答案提示让原场景变绿。

这里的发布仅写 fixture 的本地 JSON 状态，不连接真实环境。前向测试是有限场景的执行证据，不保证不同模型、宿主或每次调用都产生相同决策。

## 比较有没有改善

准备两组相同输入，生成器本身不调用模型：

```bash
# 输出路径必须尚不存在。用 --case 缩小到此次改动相关场景，可重复指定。
python3 tests/behavior/create-fixtures.py /tmp/ssf-current --case build --case recovery-build --case terse-build
python3 tests/behavior/create-fixtures.py /tmp/ssf-baseline --without-skills --case build --case recovery-build --case terse-build
# 比较新旧版本时，用旧版的 skills 目录替代 --without-skills：
# python3 tests/behavior/create-fixtures.py /tmp/ssf-previous --skills-from /path/to/previous/skills --case recovery-build
```

`fixture.json` 记录技能内容摘要、场景及 `model_execution: not_run`，仅作为输入来源信息，永远不是执行结果。后续真实结果记录在现有任务计划中，不覆盖该标记来冒充运行。两组请求、项目规则、代码与测试相同；无技能组不复制技能，也不在 catalog 暗示应选的入口。

正式对照使用相同模型、推理配置、工具权限与预算，各自从全新会话开始。提供对应 catalog 和请求；不能让无技能组继承全局 SSF 规则、上一组上下文或预期答案，也不能让任一组读取其他组和评估说明。无法隔离时标记为受污染的观察，不报告为因果对照。生成器只准备目录，不提供宿主沙箱或自动隔离保证。

先按上表定好成功条件，再查看真实文件、操作记录和结果。每个场景分别记录：

| 维度 | 可接受的证据 |
|---|---|
| 任务结果 | 修复后的公开行为、可复现的审查发现、计划/发布的实际产物 |
| 使用证据 | 读取了哪份 skill、哪些方法对应哪些操作；仅有启用宣告不计入 |
| 约束与回归 | 无关改动保持、只审查不修复、授权不扩张、无额外阶段确认 |
| 交付可信度 | 通过/失败/未验证与原始工具结果一致，简短模式不丢失关键边界 |
| 额外代价 | 实际额外确认、无关读写、重复验证；耗时/token 只记录宿主实测值 |

有技能组和对照组都成功时，结论可以是“此场景未观察到增益”；正确性变差、误报或成本增加也要保留。先区分改进方法和增加播报，不能因出现技能名称就判定效果提升。需要稳定性结论时重复独立试验，保留失败，不用一次成功泛化触发率或质量。

本目录的 Bats 测试只验证生成器输入可比、缺陷 fixture 存在与目录保护，不执行模型。未做真实对照时，报告“评估准备完成，模型效果未验证”。

## 中文触发与原始证据

`chinese-triggers.json` 的二十个自然请求覆盖七入口、组合和普通问答负例，包括修复附带自测、测试先行修复、失败恢复、只验不修、已修后的独立回归、带代码的解释及含工程词语的改写。`--case zh-fix` 等名称生成相同底层项目，`expected` 只保留在评估侧；组合场景的 `allowed` 表示允许按授权续接的入口，不把明确要求“验收后修复”的合理组合误判为串用。不要分词或用英文关键词计分；新上下文读取 catalog 和原请求后，以实际读取、操作及产物核验选择。未执行的样本明确写未验证，单次观察不能当稳定触发率。

验证真实全局安装时，不向执行者提供复制的 catalog 或技能，也不提供预期入口；让宿主按已安装元信息发现技能，核对实际读取路径、命令输出和产物。此时 `--without-skills` 只避免向临时目录复制技能，不能称为无技能对照。相同表达的各轮使用全新上下文与独立原始项目；记录全局文件摘要、每轮读取和授权边界，失败结果不得丢弃。

`intent-switches.json` 验证连续会话：每组在同一执行者内依次经历问答、局部修复与自测、单独验收、发现另一个缺陷、只读收尾；三组换用不同中文表达。只传当轮原请求，预期入口留在评估侧，不暴露后续任务。真实项目先连同未提交工作完整复制，仅在隔离副本回放有来源的历史缺陷，并先执行当前代码与回放代码的测试，避免把回放失败报告成当前产品问题。每轮冻结文件摘要，结合真实工具返回内容、命令及退出码判定行为；已经读取且未变化的 QA 可以复用，不能以“没有重读”误判未使用，也不能只凭口头声明判定正确。两条补充事实解释/方案比较控制是在发现边界问题后加入，不替代原始失败样本。九轮续接不等于强制压缩或上下文极限测试，具体观察和限制记入现有计划。

`compaction-switches.json` 在三组真实项目隔离副本中延续问答、局部修复、只验收限制，再通过本机 Codex app-server 的 `thread/compact/start` 触发原生手动压缩。只有同一 thread 收到 `contextCompaction` 的 started/completed、匹配的 item ID 和成功 turn 终态后，才能计作压缩完成；RPC 返回 `{}`、手写摘要或新建会话均不能代替。压缩后不重发“只验收不修复”，用自然续接请求检查历史限制是否保留，随后再次压缩并切换为问答、验收收尾。保存公开命令与实际输出、压缩生命周期、token usage 及逐轮文件摘要，排除推理正文；只验收轮源文件与测试必须保持。手动压缩不等于触及上下文阈值，当前全局规则继续可用也意味着这不是单独评估压缩器的因果对照。

其中 `automatic_threshold_control` 单独验证默认窗口附近的自动压缩：沿用宿主模型和阈值，不调用手动压缩、不注入摘要、不调低窗口；将真实副本源码作为明确标记、可重复的压力材料，按实际 token 使用量逐步加载。首轮明确“不新增、不修改、不删除任何项目文件”，压缩后的验收不重发限制；随后以新请求仅授权一个函数和紧邻注释，再转回独立验收。预期入口和写入范围留在评估侧。必须取得原生压缩成对事件、成功终态、压缩前后计数、完整技能读取输出与逐轮文件和操作核对；空记录不能通过。重复源码属于合成上下文压力，不等于同等长度的自然业务对话，也不能据此声称跨模型稳定率或性能收益。

本组预设零写入，新增测试也算写入，不能以“未改业务代码或原有测试”计作零写入通过。第三种表达“代码、测试和文档都保留”对新增补验存在解释空间，应同时保留原文、预期未满足和这种限制，不直接归因于压缩丢失授权，也不等同于越权修复业务。反向控制在压缩后明确重新授权局部修复，再压缩并验收，用来检查只读限制不会阻止新的合法授权，也不会把局部修复扩大到其他缺陷。协议接收中断的尝试保留为未完成，改进评估设施后使用原始副本重跑，不将接收成功当成任务通过；不满足预设标准时保留原始产物并明确记录。

`check-specialist.py <case> <project>` 独立核验专项公开行为。它要求完整的固定检查清单及严格布尔值，并检查 README 约定的固定输入；空跑、缺项、异常或改写测量脚本以 `incomplete` 失败。指标不能代替断言。本工具不是不可信代码沙箱。

离线评估需要留证时，使用一次性目录直接保存命令输出，无需为普通业务任务启用记录器：

```bash
python3 tests/behavior/capture-evidence.py run --timeout 60 /tmp/ssf-current build /tmp/ssf-build-check -- python3 -B -m unittest -v
python3 tests/behavior/capture-evidence.py verify /tmp/ssf-build-check
```

`stdout.bin`、`stderr.bin` 保存原始字节；`receipt.json` 绑定命令、cwd、时间、退出码、输入/技能及前后项目摘要。失败、超时也保留记录，不覆盖旧目录；验证后代码或输入变化会使旧证据失效。退出 0 只表示该命令成功，hash 只帮助发现缺失、意外改写或陈旧输入；两者都不能证明模型效果或抵御恶意伪造。仅在无真实凭据的离线 fixture 中运行，记录不上传。模型执行报告、技能读取轨迹和判定仍与命令证据分开记录，不能篡改 `fixture.json` 的 `model_execution: not_run`。

## 按缺口推进

`gap-cases.json` 保存小型和专项场景；`complex-cases.py` 确定性生成复杂检索与真实交接的初始材料，并复制 `browser-fixture/`。执行者只读取生成后的项目与技能目录；本说明和核验标准留给评估者。先保留当前版快照，再用相同输入比较有依据的候选修改；当前版已满足目标时不为制造增益追加答案提示，也不把两组同样成功写成候选提升。

`search-contract` 有十二个直接消费者和一个 v1 映射，能检验只读取前十处匹配造成的遗漏，但规模不足以证明大仓检索吞吐；`resume-work` 是新会话面对过时计划与脏工作区的恢复演练，不执行宿主压缩；`qa-evidence` 只测证据判断和最小后续动作，材料是离线合成记录，不是浏览器操作或视觉识别测试。不能把这些结果扩大解释为真实浏览器、真机、生产或压缩机制通过。

对修改的方法使用同输入、独立新会话复验，并按影响选择轻量负向场景（如 `terse-build`）检查额外计划、访谈或重复验证。只保留改善实际结果或解决已证实缺口的最小改动；样本不足时报告观察结果，不宣称稳定提升。

复杂场景按需单独准备，不要求每次执行模型：

```bash
python3 -B tests/behavior/create-fixtures.py /tmp/ssf-complex --case search-large --case resume-handoff --case qa-browser
```

`resume-handoff` 的第一次请求仅授权定位、复现和交接。保存第一会话实际产物后，由评估者模拟用户在 `display_name` 和 `notes.txt` 的新文案改动；再启动不继承历史的第二会话，请求“根据 notes/download-plan.md 继续修复、验证并更新该计划，保留现有其他工作”。不把第一会话报告、已知缺陷答案或评估标准注入第二会话。该方法验证文件交接，不能代替宿主原生压缩、进程重启和上下文保留机制验证。

`qa-browser` 由评估者从生成后的项目运行 `python3 -B server.py`，把输出的随机回环 URL 提供给执行者。使用本次新建的浏览器标签页，不操作用户现有标签页。测试允许修改虚构账号设置，只允许在 `runtime/` 保存证据；结束后由评估者清理自己启动的进程。没有浏览器工具、视口控制或截图能力时保留未验证项，不用直接 HTTP 调用或源码 CSS 推断冒充浏览器交互。Bats 中的服务集成测试只证明测试服务工作，实际浏览器结果单独记录。

这些规模和故障均为合成输入。即使真实工具执行成功，也不等于真实大型业务仓库、生产网页或移动设备已验收。

性能与业务语义方法比较复用 `--skills-from` 的旧版对照，按需选择 `performance-list`、`business-cancel`、`business-discuss`，用 `terse-build` 检查普通任务是否额外读取专项或创建流程文件。性能执行者实际运行 `benchmark.py`；评估者对原始实现和两组结果再用相同脚本交错复测，分别记录查询次数和耗时分布，核验脚本/Store 未改及行为保持。每次查询的 0.5 ms 是人为模拟往返，不得外推生产延迟；“夹具优化有效”与“新技能优于旧技能”分别判断。文本字符/字节增量、实际读取参考可以说明上下文负担，但没有宿主用量数据时不能换算为 token 或节省百分比。

## 五组专项验证

`specialist-fixtures/` 保存原始项目，`specialist-cases.py` 读取其中的 request 和文件；`changes/` 仅在初始提交后应用，不以该目录复制给模型。契约、幂等、验证标准、队列/回填四组使用五个专项项目；第五组自然触发复用这些请求以及 `plain-question`、`terse-build`。总共七次独立模型执行即可覆盖本轮组合，不必为每个入口重复跑一遍。

先固定技能快照和评估条件，再独立执行。评估者可运行以下命令检查产物，**不得将核验器、评分条件或其他组结果提供给执行者**：

```bash
python3 -B tests/behavior/create-fixtures.py /tmp/ssf-specialist --case wire-api --case payment-retry --case review-gates --case queue-worker --case backfill-ledger --case plain-question --case terse-build
python3 -B tests/behavior/check-specialist.py wire-api /tmp/ssf-specialist/wire-api
```

核验器也支持 `payment-retry`、`queue-worker`、`backfill-ledger`，每个进程仅加载一个项目。它校验公开行为，不代替执行记录、只读范围、测量文件完整性、注释及读取有界性的复核。审查场景由评估者核对发现、反证误报，并比较项目原始文件及 diff；可在内存恢复跳过的测试或在 shell 执行器边界注入失败，不能在只读项目写入故障。

队列时间是固定时钟的 tick，支付网关是受控替身，回填使用本机 SQLite；没有覆盖真实支付、分布式进程持久化、数据库集群和生产负载。重建 Service 不等于完整进程崩溃恢复。此批模型读取的是明确写出的项目契约，因此不能外推规格缺失时仍能自行发现所有规则。原始项目应在独立核验器中暴露预设缺陷；Bats 只验证这一事实和输入可比，不把生成及检查夹具冒充模型通过。

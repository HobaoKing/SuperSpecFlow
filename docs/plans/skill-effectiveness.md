### 明确保留、不再重复加的能力

根因调试、一次一个关键假设、公开行为 TDD、失败敏感性验证、先找已有能力、沿实际消费者查契约、真实终态及拒绝无副作用、兼容发布和恢复、精确暂存及用户脏改动保护，均已存在。上游相同原则不构成新增理由。视觉/设计也应优先使用宿主已安装的相关技能，SSF 负责触发与验收，不内置第二套设计体系。

`ssf-git` 本轮没有找到足够有依据的新方法缺口；不为了七个入口都“有改动”而增加内容。对 source-driven、复杂恢复、关系不变量等已经有原则的方向，先扩验证，失败后再决定是否需要文字修改。

### 上游不能照搬的部分及具体反证

1. **固定审批和强制流水线。** Addy doubt-driven 每轮强制询问跨模型意见，gstack office-hours 即使完整方案也要求前提/替代方案阶段，Matt wayfinder 依赖 issue/票据和每会话步数。这些约束不适合当前自主续接、七入口及一份计划的约定。保留反证、依赖、前提检验，方法深度随风险而定。
2. **固定数值和自动基础设施。** 不采用通用覆盖率、固定 QA 分数、统一性能预算或“每项非平凡改动都启新 reviewer”；不自动安装浏览器、监控、hook、记忆系统，不自动录制会话/升格全局偏好。ECC learning 的项目隔离思想可以借鉴，观察频率与自设 confidence 不能当真实正确概率。
3. **网页测量脚本有适用边界。** gstack benchmark 模板以 `transferSize` 累计资源并给通用阈值；本次只做源码检查，没有运行该测量，也没有证明它在当前缓存/跨域/交互条件下能准确评价页面。只能参考采集和比较结构，不直接采纳预算或把单次页面加载当所有交互性能。
4. **模型评分也需被审查。** `gstack/test/helpers/benchmark-judge.ts` 的该条路径将 prompt 截到 4000 字符、各回答截到 3000 字符，并在评分输入中暴露 `modelUsed`。因此此路径存在不盲评和丢失尾部证据的限制，不能用其综合分替代真实行为。此发现不代表 gstack 所有 eval 都如此；另有 native probe 和确定性判据。
5. **ECC 评分示例会丢失失败退出码。** `skills/eval-harness/SKILL.md` Code-Based Grader 示例使用 `command && echo PASS || echo FAIL`。本机用无副作用替身 `false` 验证同一控制结构：stdout 为 `FAIL`，退出码却为 `0`。若只消费退出码会误判；若解析输出可识别。仅证明示例不能直接作为退出码门禁，不声称其所有评估实现失效。
6. **测试删除和迁移回退不能绝对化。** Matt DEEPENING 的 replace-don't-layer 需先证明新测试覆盖旧行为；按源码字符串检查的测试可能正在保护包内容契约。Addy migration 的“每次都有 down / 新增均安全”也不能替代宿主数据库锁、不可逆数据变换及向前修复方案。我们现有区分代码回滚/数据恢复/补偿的原则应保留。
7. **浏览器收益分清工具与文本。** 当前 gstack 的 `ARCHITECTURE.md` 已包含 Aside 优先和 `$B` fallback 两条路径，`snapshot.ts` 有交互过滤及差异输出。工具的状态复用/快照压缩能力不能通过复制 SKILL.md 获得，也不能假定我们的 CUA 缺少相应能力。不移植其工具栈，先在现有宿主内测真实工具开销。
8. **摘要与脚本并非天然更可靠。** Addy floor-guard 的正则适合作为线索；例外、测试迁移及文档中的代码样例可能误报。gstack context-bill 明确区分估算与特定 provider 的计数，不能拿其英文/特定 tokenizer 比例换算本项目中文 token。

### 建议下一轮的最小验证组合

先做五组当前版基线，保持旧/新请求、项目、模型设置及工具能力一致：

1. API 合同漂移：真实 JSON 与 mock 在大 ID、null、错误响应上不一致。
2. 幂等延迟重放：同键异载荷、并发、已执行后超时及 key 保留期不匹配。
3. 验证标准被弱化：移除断言、加 skip、忽略项，附合法测试重构作为负例。
4. 队列/回填：中位数正常但积压/陈旧增加，批处理重复漏行和中断恢复。

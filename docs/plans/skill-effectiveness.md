## 工程方法落点

| 入口 | 原指导的不足 | 本次完善 |
|---|---|---|
| think | 说明建议但缺少形成建议的办法 | 分开目标与手段、事实与推断；检查会推翻方案的前提；比较最小有效改变 |
| plan | 有任务和验收字段，缺少拆分依据 | 先验证关键未知，按完整行为切分；明确依赖和失败结果；自查需求覆盖与契约一致 |
| build | 原则和简短参考无法指导复杂决策 | 先找项目能力；追踪接口消费者；逐步贯通；正常路径对照、首个失真边界与假设反证 |
| review | 只说检查正确性，风险选择与误报排除不具体 | 按变化信号选数据、权限、异步、枚举等路径；主动检查已有保护；按根因合并发现 |
| qa | 报告规范强，选什么测、怎么判失败较弱 | 按风险选择层次与旅程；检查测试价值、失败原因、恢复和最终状态 |
| ship | 有检查项，缺少中间状态推演 | 证据绑定候选版本；新旧组件兼容；区分代码回滚与业务补偿；未知结果先查证 |
| git | 精确暂存不足以排除既有无关暂存 | 核对真正提交内容、按行为组织提交；冲突解决后复核契约与受影响验证 |

具体固定来源与本地采用关系见 `NOTICE.md`；不扩大上一轮的诊断脚本或评估基础设施，本轮交付重点在 skills 及其方法资源。

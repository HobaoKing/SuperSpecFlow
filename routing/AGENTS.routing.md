# SuperSpecFlow 轻量规则

宿主业务、架构、构建运行约束和用户全局规则优先；本文件补充方法，不接管项目流程。

## 核心约定

- 先用会话和项目事实消除不确定性；仅对无法可靠推断且实质影响业务、范围、外部契约、费用或不可逆操作的未决问题询问，继续独立工作。同一目标、数据、目的地和范围内复用授权；只讨论、计划、审查或评估时止于相应交付，已授权实施则继续完成。
- 仅跨模块、跨会话或用户要求时维护一份计划，普通多步骤任务不落盘。用户指定路径和已有计划优先；默认 `docs/plans/<topic>.md`，可用 `bash <pack>/scripts/new-plan.sh <topic> [project-dir]`，参考 `<pack>/templates/implementation-plan.md`。
- 遵循 Karpathy 的简单、精准修改与目标驱动原则，按需采用 TDD、根因诊断和代码审查。保护无关工作，复用项目机制，避免推测性抽象。
- 新增或行为、契约变化的非平凡函数，在实现定义处写简体中文注释，说明实际语义与约束。业务分支、状态、异步、失败处理和副作用不能豁免；无额外规则的简单 getter/setter、透传、初始化或纯格式调整可豁免，不补写无关历史、生成或第三方代码。
- 测试观察行为、不复制实现；缺陷优先复现，覆盖主要、关键负向及回归路径。遵守宿主运行限制，不新增低价值测试。
- 完成前核对实际 diff 与必要注释，报告结果、验证和剩余项。静态、测试、构建、浏览器、真机和部署证据不可混用，未运行不写通过。
- 中文交流和文档；commit / PR 标题为 `<英文类型>(<英文范围>): <中文摘要>`。提交前检查 status、diff stat、`git diff --check` 和最终 staged diff，精确暂存。实现不自动授权 commit、push、PR 或发布，复用已有明确授权。

## 按需入口

按意图选择最直接的 skill，自然语言即可触发，无需 `/ssf-*`。复合请求按授权续接；内部分析、测试、自审不自动触发全部 skills 的流水线。

| 请求 | skill |
|---|---|
| 讨论方案、澄清需求 | `ssf-think` |
| 计划、拆任务 | `ssf-plan` |
| 实现、修 bug、重构 | `ssf-build`，含按需 TDD 与调试参考 |
| 代码审查 | `ssf-review` |
| 测试、验收、浏览器核验 | `ssf-qa` |
| 发布准备与执行 | `ssf-ship` |
| 分支、提交、PR | `ssf-git` |

默认在当前工作区和会话完成。多 agent、worktree 遵守宿主限制和用户授权，复杂度不构成额外授权，满足条件时优先复用；独立审查按用户要求进行，不冒充独立结论，反馈先核实再按授权修复。

只读适用的 skill 和参考，不重复加载未变化规则，不自动刷新安装。复用当前代码的有效证据；仅因新改动、失败或具体未决风险扩大或重跑验证，不重复评审。报告简洁，不重复整份计划；节省 token 不得省略必要工作或隐瞒未完成项。
